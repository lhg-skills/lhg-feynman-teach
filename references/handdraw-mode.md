# 手绘模式 Handdraw Mode（可选视觉模式）

## 定位

幻灯片模式是默认：快、稳、够用。手绘模式是可选升级：当“一步步画出来”比“直接放一张图”更有助于理解时，才用。

手绘模式不是把幻灯片换个皮肤，而是换一种讲解节奏：声音先定，画面跟着声音一点点长出来，观众跟着笔尖走完因果链。

## 什么时候用手绘，什么时候不用

用手绘：
- 过程 / 机制 / 因果链：需要按顺序展开，一步推下一步
- 结构 / 对比 / 时间线：需要边画边讲，看到部分与整体的关系
- 抽象概念需要具象化：一个类比能画出来，而不是只说出来
- 用户明确说“手绘”“白板动画”“画出来讲”

不用手绘（继续用幻灯片）：
- 纯定义、纯公式、代码、数据表：画出来不增加理解，反而慢
- 需要精确截图 / 真实界面 / 真实照片：手绘会失真
- 赶时间、只想快速验证讲稿：先出幻灯片版，确认讲通后再决定是否重做手绘版

决策写进 `video/script.md` 一句话：为什么本期选手绘 / 幻灯片。

## 手绘模式管线（讲稿锁定之后才开始）

1. **声音先行**：先锁定完整旁白，再按旁白的实际时长排画面。画面适配声音，不切碎旁白去迁就画面。无配音工具时，先输出带停顿标记的旁白文本，不出无声片。
2. **分镜到句**：把讲稿按句切镜头，每镜头写：旁白句 / 要画什么 / 画完后观众应该看到什么事实 / 时长 / 字幕。
3. **可绘制检查**：每张图先写绘制计划，再出图。计划写清：主体是什么、分几个部位、按什么顺序画、每个部位的轮廓怎么走、哪些事实必须在画面里真实可见（不能只靠字幕或标题代替）。没有可执行计划，不调用生图。
4. **先轮廓、后填色**：整幅图先完成全部轮廓，再按同一顺序填色。笔画独立，笔间抬笔；相邻笔画即使共用端点也要有抬笔间隔，断开的线不串接。每个字独立成形，前字未完成不露出后字。
5. **按部位拆，不按矩形切**：人物与场景按语义部位拆（例如头、颈、躯干、左右臂、下半身、道具），处理遮挡，看不到的部位记遮挡原因，不虚构轮廓。不把整个人或整个场景标成一个部位，也不按矩形草率切碎。
6. **手与笔（可选）**：手绘笔尖可配手臂或仅画笔。手臂按笔尖到手腕校准，裁切边留在画外；仅画笔按完整笔身校准。笔杆广告、水印默认不加，用户明确要求才加，且不杜撰品牌或署名。
7. **字幕唯一性**：同一句旁白在同一时刻只显示一份字幕。禁止画面烧录 + 字幕轨 + 外挂字幕文件多层叠加。默认白字、黑色细描边、无底板。
8. **先验代表段，再渲整片**：先渲染一段覆盖文字、插画、上色、字幕与转场的代表段，检查笔尖、手臂、遮挡、阅读停留、声画对应，通过后再渲整片。
9. **质检后交付**：检查工程、画面、动作、内容、声音五类证据，发现失败修对应层后重渲。未实际听音，不声称听感已验收。交付时明确告知是否含背景音乐（默认不含）。

## 失败与降级

- 无生图工具 / 无描线与手臂合成能力 / 无逐词时间戳能力时，不谎称已生成手绘成片。输出手绘待制作包：`drawing-plan.json`（绘制计划）+ 出图提示词 + 笔画顺序 + 时间映射表 + 旁白 + 字幕，由人工或专用工具按包制作。
- 某张图看图检查不通过：停在该图，不进入下游构建，修图后重检。
- 手绘模式耗时明显高于幻灯片模式，同一主题先出幻灯片版验证讲稿，再做手绘版，避免在没讲通的讲稿上花绘制成本。

## 与费曼门禁的关系

手绘不降低费曼门禁，反而更严：画不出来的概念，说明还没讲通。绘制计划里写不出的“必须可见的事实”，就是卡点，要回第 4 步补漏，而不是用漂亮画面盖过去。

## 来源与归属

手绘模式的制作思路参考 `threerocks/sweety-handdraw-video`（MIT，见 `references/upstream-tracking.md`）。本 skill 没有复制其代码与素材，只吸收了可复用的流程要点（声音先行、绘制计划、分部位描线、字幕唯一性、代表段检查），并按费曼教学的“讲稿即旁白、画面服从讲稿”重新组织。上游的完整实现、脚本与素材以其仓库为准。
